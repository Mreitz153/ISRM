# Contributing to ISRM

ISRM is published openly to encourage independent technical review, implementation, falsification and discussion.

## Useful contributions

Contributions are particularly welcome in the following areas:

- independent mappings of real systems to ISRM
- independent reference implementations
- conformance and edge-case tests
- counterexamples and falsification attempts
- ambiguity reports
- comparisons with relevant standards and prior art
- proposals that improve interoperability or testability

## Version discipline

The canonical ISRM v1.0 publication is frozen and archived at:
https://doi.org/10.5281/zenodo.23115842

Corrections or proposals discussed in this repository do not silently alter v1.0. Substantive semantic changes belong to a future version.

## Issues

For technical discussion, open a GitHub issue and state:

1. the ISRM concept, clause or invariant concerned;
2. the system or scenario being considered;
3. the observed ambiguity, conflict or counterexample;
4. the proposed resolution, if any;
5. supporting references where applicable.

## Scientific and standards discipline

Please distinguish documented evidence from interpretation. Prior work should be cited. Claims of novelty should be narrow and supportable.
